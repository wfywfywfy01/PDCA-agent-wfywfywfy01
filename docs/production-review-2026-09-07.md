| 类别 | 根因与处理 |
| --- | --- |

| 写入真实性 | 物流与任务主存储失败返回失败；已写入 Markdown/CSV/VPS 的辅助数据库镜像保持兼容。 |
| 权限与会话 | 禁止 SSO 复活停用账号、按同名自动授予业务权限、将导出复验凭证当登录凭证；修复 VPS 模式 SSO 会话、限速和非法跳转。 |
| 用户流程 | 修复资料原件的复验/授权/下载契约、切日期竞态、错误吞掉、五件套重复覆盖确认、会议派发日期及窄屏导航。 |

| 发布回滚 | 前后端测试通过后才发布镜像；两个 Compose 使用正确构建上下文；校验镜像和公网版本、SPA 资源；停机/改名失败也恢复原容器；保留最近一份完整回滚配置。 |

| 验收可信度 | 生产验收脚本不再创建/删除管理员，不把来源标签当作对账豁免；使用现有账号只读检查和独立快照总额。 |

## 验证与发布门禁

- 后端：`python -m unittest discover -s tests -p 'test_*.py' -q`，以及 `compileall`。
- 前端：`npm test`、`npm run typecheck`、`npm run build`，均纳入镜像构建。
- Compose、Bash、PowerShell 语法和 `git diff --check`。
- 隔离浏览器 24 项验收，包含下载事件、取消覆盖不写入、失效会话和 11 页手机布局；全部是 QA 数据，不作为生产经营数据证据。
- 本地真实 PostgreSQL 验收：6 路同店同日提交只存 1 行，真实零覆盖、负责人隔离、越权拒绝、数据库停止后健康变为 503。
- CI 同时运行 SQLite 容器冒烟和 PostgreSQL 隔离验收。只部署 main 上明确提交对应的已测试镜像。
- 发布后运行 `scripts/acceptance_smoke.py`（凭据仅通过环境变量传入），检查两个公网入口并独立对账；生产验收结果以对应部署日志为准。

## 已知边界

- 数据库可连接不代表上游业务源完整；缺数应显示 N/A，不据此认定数据“全部正确”。
- 存量负责人/SSO 姓名映射不批量清空；仍需业务管理员核实历史授权。
- Odoo 完整单点登录需要 Odoo 端配置与共享密钥，本轮不擅自启用未配置的集成。
- 管理员弱密码、Docker API 的 TLS/网络访问控制需要账号和基础设施负责人落实；本轮不改共享 Caddy 主机的其他服务。
- 不将资料库外部 worker、上游服务状态冒充 PDCA 本轮已修复项。
