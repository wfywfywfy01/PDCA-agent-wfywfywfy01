# 小黑屋群任务跟进

## 执行方式

- 仅从配置的管理员真实 `sender_user_id` 识别派单，正文冒用管理员名字无效。
- 定向任务按明确负责人建立；面向全员的任务展开为在群的普通成员，排除管理员、群主、机器人及明确的数据分析支持岗位。未能确认的派单不推测负责人。
- 默认上海时间 10:00 提醒任务，20:00 拉取群消息核对提交。时间可通过环境变量调整。
- 保留管理员公布的任务起止日期与具体截止时间；只写日期时截止为当地当天 23:59:59。未来任务不提前追，多日任务不要求每天重交。
- 视频任务需要实际视频与任务上下文对应；邻近的同人文字说明与媒体可以关联。只有“已交”或任务标题不算已找到交付，引用图、不可读或不明确的附件保持待确认。
- 找到交付证据时登记 `evidence_submitted`，保留消息来源。这表示找到提交，不表示已通过内容质量验收。
- 历史页失败、窗口不覆盖任务起点等情况不判缺交；每日重复任务进入人工核对。失败发送不写已提醒，重试使用同一幂等键。
- 小黑屋任务由专用轮次处理，不参与经销商群的普通催办、自动扣分、OKR 关联或 CSV 覆盖。

## 部署配置

以下配置不含真实群、身份或凭据。配置文件不得提交 Git。

```dotenv
PDCA_HEIWU_TASKS_ENABLED=1
PDCA_HEIWU_CHANNEL_ID=<目标群ID>
PDCA_HEIWU_TASK_PUBLISHER_USER_IDS=<管理员用户ID，多个以逗号分隔>
PDCA_HEIWU_TASK_EXCLUDED_NAMES=<排除的完整姓名，英文逗号分隔>
PDCA_HEIWU_TASK_EXCLUDED_USER_IDS=<排除的用户ID，英文逗号分隔>
PDCA_HEIWU_TASK_MORNING_TIME=10:00
PDCA_HEIWU_TASK_EVENING_TIME=20:00
PDCA_HEIWU_TASK_LOOKBACK_DAYS=21
```

发送身份有两种明确配置，不能把 App ID 当作已经验证的发送凭据：

1. 专用用户机器人：配置 `PDCA_HEIWU_BOT_APP_ID` 与 `PDCA_HEIWU_BOT_APP_SECRET`，通过机器人推送接口发送。
2. 平台通知机器人：配置已经验证的 `PDCA_HEIWU_NOTIFY_AGENT_SLUG` 与 `PDCA_HEIWU_NOTIFY_BOT_NAME`，通过已认证 CLI 的 `im +agent-notify --target im` 发送。此身份与原用户机器人不是同一对象；首次使用新 slug 时平台可能注册通知机器人，投产前须确认实际 sender ID。

任务开关独立于旧的 `PDCA_HEIWU_ENABLED` 开单祝贺开关，不因启用任务跟进而自动开启祝贺。

排除名单只作用于小黑屋任务：全员、点名派单均跳过，早晚发送前再次检查。
姓名按任务负责人的完整名称精确匹配，不做子串、同音或繁简转换。新任务优先采用员工正式姓名，
没有时依次回退昵称、备注、登录名；不使用其他别名推断同一人。应同时配置已核实的用户 ID，
以覆盖改名、退群及尚未入群的账号。配置变更需重启服务。
下一次同步或证据核对会将排除人员的未关闭任务停止为 `complete/excluded`，
追加 `owner_exclusion` 事件，保留原派单、提交证据及催办次数；这表示不再跟进，不能视为完成交付。
已终结任务不改写。即使群消息或成员采集失败，已有任务仍按排除名单停止，不发催办。

## 采集与业绩口径

督战官图片使用现有 Qwen 识别，成功结果按附件身份复用；队列按负责人轮转，避免某人的多张图占满全部预算。超时、下载失败、未识别或截断均保留待确认，不能记成 0。

同一次图片识别区分 MTO 报价、付款凭证、业绩报表与其他图片。可见金额、币种、状态和来源保留为群内申报证据；系统已录单业绩仍来自正式销售接口。群内水单、意向、报表不直接叠加到正式业绩，避免重复计算。无法读清的图片保留待核来源，不估金额。
