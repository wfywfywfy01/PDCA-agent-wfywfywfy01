# 督战官群聊规则卡片

生产使用 `PDCA_DUZHAN_COMPACT=1`：早追只列目标、今日／本周待办和 MTO 计划；中追只列简短进度、未闭环事项和回复要求；晚追核对业绩、事项闭环、MTO、日报和证据，并列出明日第一动作。自定义时间沿用早／中／晚三个阶段；`0` 保留历史长版以供排查。

月度目标在 `app/monthly_sales_targets.json` 维护。`department_target_wan` 是海外合计，`departments` 是部门分解，`entries` 仍是已确认的个人／小组计划；部门目标不自动平摊到个人。定性破零目标写 `goal: "break_zero"`，显示“破零”，不作为数值零参与达成率。2026 年 10 月海外目标为 1600 万：二部 800 万、三部 400 万、四部与一部各 200 万、五部破零。

管理员打开 `/app/admin/duzhan-agents`。先导入现有督战群，或新建一张卡片；选督战官已加入的目标群、10:00 / 15:00 / 20:00 档位，再按需插入发送条件和动作规则。规则从上到下匹配，第一条命中的固定或 AI 动作替换消息里的“本档动作”。AI 失败时继续找下一条规则，仍无结果则使用原有档位文案。C 转 B 群没有日报字段，不能使用“有人未交日报”。

保存后可选择日期和档位试跑。试跑只读已有快照台账，不取业务数据、不向群发送消息；没有快照时会显示待确认数据。AI 试跑会调用模型并计入当日额度，但不会写入正式发送缓存。

页面顶端显示当前配置来源。`PDCA_DUZHAN_CONFIG_SOURCE=code` 时，卡片只供预备和试跑，线上仍按代码配置发送。接管步骤：

数据库模式按时区和档位合并达标群采集、按档位合并 C 转 B 群采集与发送；消息仍逐群发送并使用各群幂等键，避免多张卡片同时请求同一数据源。

1. 确认生产 Agent 凭据有效，服务健康检查通过。
2. 导入并核对现有群，逐群试跑，确认应继续发送的每个群已启用，且同一群只有一张启用卡片。
3. 将 `PDCA_DUZHAN_CONFIG_SOURCE=db` 写入生产配置，发布明确 Git commit 并重启服务；核对注册的群和档位与预期一致。
4. 核对首档发送结果。修改文案和条件会在下一档采集或发送时读取；修改目标群、档位或启停状态后重启服务以更新调度。

回退配置来源到 `code` 并重启服务即可恢复代码里的群清单。页面的试跑不会替代真实发送核验。
