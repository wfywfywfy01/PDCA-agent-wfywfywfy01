# 督战官：群聊配置与 VPS 接入

管理入口：部署地址下的 `/app/admin/duzhan-agents`。使用 PDCA 管理员账号登录。
日常配置只需选群、选规则和填写指标；群 ID、JSON 与机器人凭据不需要由普通使用者填写。

## 先选适合这个群的督战方式

| 方式 | 适合的群 | 配置内容 |
| --- | --- | --- |
| 通用群任务 | 在 VPS 群内派发任务、提交交付物的团队 | 目标群、可信发布人、排除人员、提醒时间与时区 |
| 部门业绩 | 已接入销售与过程数据的部门群 | 月度目标、MTO 指标、提醒时间、提醒条件与重点文案 |

通用群任务可以接入固定督战机器人已加入、服务端可读取的新 VPS 群。
部门业绩依赖已有业务数据映射；选择一个新群不会自动得到该群的销售或 MTO 数据。

已有专用小黑屋群继续按原入口运行，不允许再建通用卡片重复追踪。其发布人、排除名单、
任务记录和发送身份不自动复制给其他群。详见 [小黑屋群任务跟进](HEIWU_TASKS.md)。

## 新群：五步开始任务督战

1. **新建群配置**，选择通用群任务。
2. **选择 VPS 群**。选择标记为可接入的群；固定督战机器人必须已入群。
   无法读取成员或已有专用督战的群会显示原因，不能直接启用。
3. **选择可信发布人和排除人员**。发布人决定“谁说的算派单”；排除人员不参加这张卡片的任务催办。
   人员选择使用真实账号 ID，重名时核对账号，不能只凭名称猜测。
4. **设置时间**。默认早上 10:00 提醒，晚上 20:00 核对提交；可修改到分钟，
   并选择时区。时间按早、中、晚阶段执行：早中提醒待办，晚间核对交付证据。
5. **保存草稿、看预览、再启用**。新卡片默认停用；保存和预览不会向群里发消息。
   启用时会重新核对群、人员与机器人入群状态。

通用任务调度每分钟读取已启用卡片，允许在计划时刻之后 5 分钟内触发本档检查。
每轮采集最近 21 天消息；更早的未闭环任务保留台账，覆盖不足时标待确认。
保存后的配置由后续计划检查读取，不需要重启服务，
也不会因为点了保存就立即补发一条消息。同一群只允许一张启用卡片。

预览只读已有任务台账，不重新采集群消息。新群尚未经过首次计划采集时，
空预览表示“暂无已采集任务”，不能据此断定群里没有任务。

### 发布人怎样发任务更容易识别

发布人用自己的真实账号发清楚负责人、事项和截止日期。例如：

> @所有人 10月29-31日产品演示视频任务，请大家完成并提交群内。

或逐行写：

> 销售甲：10月29日18:00前完成客户回访并提交复盘
>
> 销售乙：10月30日完成产品演示视频并提交群内

示例名称仅用于说明，实际以群成员账号为准。普通催促、奖励公告不会被当作新任务；
不明确的负责人不会自动分配。“每天重复”的任务需要人工核对，不能把一次提交认作以后每天已交。

### 什么算闭环

| 状态 | 含义 |
| --- | --- |
| 未到截止时间 | 提醒推进任务，不要求提前重复交付 |
| 找到提交证据 | 找到负责人提供的相符消息或附件，保留来源；不表示内容质量已验收 |
| 超期且未找到证据 | 在历史消息完整的前提下提醒补交 |
| 待确认 | 采集不完整、附件不可读、对应关系不清等，不能据此判定未交 |
| 已排除 | 停止该人的任务跟进，保留历史；不表示完成交付 |

仅回复“已交”不算找到交付证据；视频任务需要实际视频与任务上下文相符。
多日任务保留原起止日期，不要求每天重交；未来任务不会提前催办。只写日期时，
截止时间为配置时区当天 23:59:59。

群历史采用完整分页。拉取失败或覆盖不足时不会把缺失数据当成零条，也不会据此发缺交催办。
发送失败不会写成已提醒；服务端按群和任务使用幂等记录，避免重试重复发送。

## 部门群：每个月改哪些指标

在部门群卡片中选择月份，填写后保存本月指标：

| 指标 | 填法 | 说明 |
| --- | --- | --- |
| 业绩目标 | 人民币万元，或选择“破零” | 破零是定性目标，不作为数值 0 计算达成率 |
| MTO 每人每天款数 | 整数 | 只计算参加 MTO 考核的成员 |
| 单款最低金额 | 人民币万元 | 用来区分已识别报价和符合考核门槛的报价 |

指标按群、按月保存，其他月份保留。保存后下一次检查读取，无需重启。
预览按所选日期使用对应月份的指标；修改未来月份不会替换当月目标。

部门按完整名单汇总，每个时段一条消息，事项仍保留负责人。
“仅追待办”成员继续追待办、闭环并计入部门业绩，不承担 MTO、正式日报及销售过程专项配额。
成员名单与角色由已有部门映射维护，不通过填写展示群名改变归属。

### 早、中、晚各做什么

- **早追**：部门目标、今日和本周待办、MTO 计划。
- **中追**：简短进度、未闭环事项、下一步回复要求。
- **晚追**：部门业绩、事项闭环、MTO、日报和证据，明确明日第一动作。

每个阶段可自定义一个时间，精确到分钟；按最近的 10:00、15:00、20:00 对应阶段。
已有 C 转 B 卡片使用上海时区，原停用状态保留。

### 提醒条件和自定义文案分别控制什么

**提醒条件**决定这个时段是否发送，例如只在工作日发送。默认不额外筛选，
按原业务逻辑检查并提醒；多条条件必须同时满足。取数失败不等同于“没有数据”。

**提醒重点**只覆盖消息中的“本档动作”部分，不代替数据采集、任务识别或证据核对。
可以选择固定文字或 AI 生成；规则从上到下匹配。AI 失败时继续使用下一条可用规则，
没有可用结果则回到默认阶段文案。AI 预览会调用模型并计入额度，但不会发消息或写入正式发送缓存。
C 转 B 没有日报字段，不能使用“有人未交日报”规则。

## 保存、预览和生效范围

| 变更 | 生效方式 |
| --- | --- |
| 新建卡片 | 保存为停用草稿，明确启用后才进入调度 |
| 通用群任务的规则、时间、启停 | 每分钟重新读取，后续计划检查使用新配置 |
| 部门月度指标、提醒条件与文案 | 下一次采集或发送读取 |
| 部门模式的目标群、时间或启停 | 仍需部署管理员重启服务更新已注册的定时任务 |
| 删除卡片 | 删除配置；不应当用于暂时停追，暂停请用停用 |

页面显示当前配置来源和总开关。海外部门使用 `PDCA_DUZHAN_CONFIG_SOURCE=db` 才由后台卡片接管；
`code` 模式仍按代码内的原群清单运行。不能只看卡片“已启用”就认定生产已发出消息。

配置结构预览只验证规则；实际文案预览使用已有台账/快照，均不向群发送。
生产发送成功与否以运行记录和实际消息回执为准。

## 在 VPS 里怎么使用

### 入口与登录

VPS 可把已部署 PDCA 的 `/app/admin/duzhan-agents` 作为督战官管理入口。
管理页使用现有 PDCA 登录与权限校验，当前只面向 PDCA 管理员。

系统已有可信代理身份和 Odoo 签票单点登录适配，但是否就绪必须读取
`GET /api/auth/config` 的 `vps_sso_ready`。为真时可经
`/api/auth/vps-login?next=/app/admin/duzhan-agents` 进入现有登录流程；
未就绪时使用 PDCA 登录，不要声称 VPS 免登已经开通。
部署对接见 [Odoo 嵌 PDCA 免登说明](../pdca-workbench/docs/Odoo嵌PDCA免登对接说明.md)。

VPS 登录成功不会自动授予 PDCA 管理权限。服务端采集凭据不是浏览器访问者身份，
禁止用服务器 CLI 登录态给所有访问者代登录，也不能从前端传一个姓名或用户 ID 提权。

### 群目录与机器人

实际服务端命令由 `app/vertu/client.py` 解析为 `vps-work`，
通过原生 VPS IM 的 `im +channels`、`im +bot-channels`、`im +history` 读取信息。
这与 Odoo CLI 的 `vertu odoo ...` 和其他平台的 `workctl` 是不同接口。

通用任务使用部署指定的督战机器人，不要求使用者粘贴密钥。
目录缺少某个群时，先核对服务端是否可读、机器人是否已入群。
加入机器人由有权限的群主或管理员处理；配置页面不会借用别人的身份绕过权限，
也不会因无法发送而自动创建或切换机器人。

### 给 AI 助手加载督战官技能

可分发的技能源文件在 [skills/duzhan-supervisor/SKILL.md](../skills/duzhan-supervisor/SKILL.md)。
整个目录可交给支持 `SKILL.md` 的宿主按其正式加载流程接入；内容不包含生产账号、
群 ID、业务人员名单、月度目标或机器人密钥。

2026-10-28 使用本机 `vps-work 2.3.0` 的 `--help` 核实：除了随包公开技能安装，
CLI 已提供个人技能创建、更新和申请公开命令。以下仅说明接入方法，本次改造未执行平台写入：

```powershell
vps-work skill +create-personal --slug duzhan-supervisor --title "督战官配置" --description "配置群任务闭环与部门督战规则" --skill-md '@skills/duzhan-supervisor/SKILL.md'
```

在仓库根目录运行；如果该技能已由当前用户创建，核对现有内容后改用
`skill +update-personal` 与相同的 `--slug`、`--skill-md` 参数，生成新版本。
命令依赖当前 VPS 身份和正式 Hermes 管理服务；服务地址由
`VERTU_HERMES_BASE_URL` / `HERMES_AGENT_ADMIN_BASE_URL` 或已核实的
`--hermes-base-url` 提供，不应猜测地址或携带他人凭据。

需要分享给企业时，由技能所有者明确执行：

```powershell
vps-work skill +request-publication --slug duzhan-supervisor --note "申请公开不含生产凭据和业务名单的督战官配置技能"
```

这个命令是**提交公开申请**，不等于已经审核通过或已出现在企业技能库。
本次仅验证了命令帮助，未验证当前账号的创建权限、目标服务连通性或发布审核结果。
`skill install` 面向 CLI 随包公开技能，不应假设它能安装刚创建的个人技能，
更不能省略名称触发安装全部技能。各宿主如何加载个人技能，以平台实际界面和回执为准。

技能只指导已授权的配置操作。加载技能不会安装 PDCA 后端、开放访问权限、替用户启用群聊，
也不会向群里试发消息。运行地址、账号权限及机器人凭据由各部署独立提供。

## 运维与接口核对

- 管理 API：`/api/duzhan-agents`；新群目录：`/api/duzhan-agents/group-options`。
- 通用任务使用唯一 `task_policy` 块，保存可信发布人和排除人的真实用户 ID；
  不从展示群名或消息正文推断身份。实际字段见 `/block-schema`。
- 月度指标使用 `/monthly-metrics`，保留月份版本校验；冲突时先刷新，不覆盖他人修改。
- 单点登录、角色和 CSRF 防护继续由现有认证层执行。卡片不提供密钥、代理身份或任意 HTTP 目标字段。
- 通用配置、小黑屋专用配置和部门销售规则各自隔离；调整一个群不会改写另一个群的名单或指标。
- 采集失败、截断、不可读图片保持待确认。群内水单、意向、报表是申报证据，不直接叠加正式已录单业绩。
- 从旧代码导入按群去重，新增为停用草稿；再次导入不会启用此前暂停的群。
- 海外运行源由代码切换到后台时，先核对所有应继续运行的群与机器人，再发布明确 commit、
  重启并核对首档回执；回退到 `code` 同样需要重启，并会使用代码群清单，不能代替逐群暂停。
