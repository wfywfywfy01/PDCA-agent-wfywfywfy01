# 经销商资料库接入与验收

## 边界

- PDCA 负责登录、角色、销售归属、门店范围和统一网页入口。
- `vertu-data-hub` 负责文件、ETL、向量、检索、引用、预览和原件导出审计。
- 两个仓库独立发布。PDCA 通过私有 API 调用 data-hub，不直连其 PostgreSQL，也不把服务密钥交给浏览器。

## 生产配置

```dotenv
PDCA_KNOWLEDGE_HUB_ENABLED=1
PDCA_KNOWLEDGE_HUB_URL=https://dealer-knowledge.vertu.cn
PDCA_KNOWLEDGE_HUB_TOKEN_KEY_FILE=/run/secrets/dealer-knowledge-jwt.key
PDCA_KNOWLEDGE_HUB_TEAM_MAP={"overseas":"overseas-sales"}
```

data-hub 使用同一密钥：

```dotenv
SERVICE_TOKEN_KEY_FILE=/run/secrets/dealer-knowledge-jwt.key
SERVICE_TOKEN_ISSUER=pdca-workbench
SERVICE_TOKEN_AUDIENCE=dealer-knowledge-hub
```

密钥文件不得进入 Git。建议生成 48 字节随机值，每次轮换时先更新两端挂载，再依次重启 data-hub、PDCA。

## 主数据映射

管理员打开 PDCA 管理后台，在每个门店填写 `资料库经销商 UUID`。同一经销商的多家门店使用同一 UUID。销售账号最终可见范围取以下条件交集：

1. PDCA `dealer_assignments` 中的有效门店；
2. 门店有效状态；
3. 门店已填写且格式正确的 data-hub 经销商 UUID。

部门公用资料使用 `team_key` 显式映射。公司公用资料可被所有已登录内部账号检索，但只有管理员可写入。

## 上线验收

1. `GET /health` 与 data-hub `GET /health/ready` 均返回 `200`。
2. 销售登录 `/app/knowledge`，经销商下拉只出现本人范围。
3. 文字查询返回原文件名、版本、页码或音视频时间戳。
4. 图片查询显示带 `VERTU INTERNAL PREVIEW` 水印的 JPEG，不返回原文件元数据。
5. 销售调用原件导出返回 `403`。
6. 管理员填写不少于 10 字符的用途并确认后可导出；data-hub `audit_event` 记录用户、资产、敏感级别和用途哈希。
7. 使用范围外经销商 UUID 查询返回 `403`，空范围账号不返回经销商资料。
8. 桌面与手机页面无横向溢出，浏览器控制台无错误。

## 回滚

关闭 `PDCA_KNOWLEDGE_HUB_ENABLED` 即可移除数据面调用，不影响 PDCA 其他功能和 data-hub 已存资料。数据库新增字段 `dealer_stores.knowledge_dealer_id` 可保留；旧版本会忽略该字段。
