# Omega 公司账号发布准备

2026-10-12。首批用户：公司销售与主管，通过账号登录。本文记录本轮修复与放行条件，不替代业务签收；历史验收表不自动升级为通过。

## 本轮修复

1. 停用账号不再执行或发布已排队的模型结果。实时语音在接入及连接期间重新检查账号、原始登录凭据、场次所有者和来源权限，主管阅读权限不等于代销售发言权限。
2. 每账号最多一场实时语音，默认全局八场。环境变量 `PDCA_OMEGA_REALTIME_MAX_CONNECTIONS` 接受1至64的整数，无效配置拒绝服务。该数是资源上限，不能当作生产负载测量结果。PostgreSQL 分配名额使用数据库事务锁，多个 Web 进程共享计数；若锁竞争影响吞吐，再按实测调整。
3. 每场连接最多30分钟；独立看门狗每四秒复查凭据并处理阻塞。达到时限先显示结束通知并释放麦克风，最终稿仍按原协议核对。未识别尾音、缺最终稿或缺关闭确认时保留失败，不强行评分。
4. 最终报告完整语义复核，逐项审查成果、九维理由、每条承诺/让步/底线事实和改写后的练习；保存模型、审核版本及内容摘要。实际分数和上限可供核对严重矛盾，合理评分差异不触发重评分。
5. 豆包静默错误码 `45000003` 使用固定提示说明超过10分钟无交谈时连接释放；可手动继续。其他错误保持原处理，供应商原始消息不透传。失败状态、尾稿完整性、权限和音频代次校验不放宽。错误码处理不等于证明本轮全部断线均由静默限制导致。
6. 格式、评分范围、引文与语义内容失败最多重试一次。校验反馈同时传给相应报告和练习生成步骤；反馈只作待核对数据，原始逐字稿仍是依据。两次失败显示错误并保留原始记录，不发布未经复核的报告。其他未列入白名单的结构错误仍直接失败，不能声称所有错误都会重试。

模型保持豆包3.0全双工（协议模型 ID `1.2.6.1`）和文字 `deepseek-flash`；密钥只在服务端。Web、worker和数据库独立运行，Codex不在产品运行链路中。

## 公司全面开放的放行条件

沿用2026-10-09的38项验收标准，逐项填当前结果及证据；任何未执行项必须保留。关键未完成项包括：
