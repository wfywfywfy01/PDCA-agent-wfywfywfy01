## 1. 生产切换三步曲（P0–P4 全部代码已就绪）

新前端（Vue3 SPA）与数据库事实源重构已随镜像构建。按以下顺序切换：

### 第 1 步：发布新镜像

按现有 CD 流程（`deploy_remote_docker.ps1` / 五件套门户用 `_walkin` 版）发布最新 SHA。
本次起镜像包含前端构建产物（Dockerfile web-build 阶段）。

### 第 2 步：切首页到新 SPA

内部工作台 `.env` 增加：

```ini
PDCA_HOME_REDIRECT=/app/
```

`/` 将重定向到新 SPA（旧页面保留共存，任何问题删掉该行即回退）。
建议同时激活告警通道：

```ini
PDCA_ALERT_WEBHOOK_URL=https://your-im-bot-webhook
```

### 第 3 步：补历史数据（一次性，先 dry-run）

在服务器（能访问生产 PG 与仓库 data_raw 的机器）执行：

```bash
python scripts/import_history_dealer_sales.py --dry-run   # 预览：每月一份快照
python scripts/import_history_dealer_sales.py             # 正式导入
python scripts/import_customers_csv.py --dry-run          # 客户台账预览
python scripts/import_customers_csv.py                    # 正式导入
```

导入器幂等（按业务键 upsert），可重复执行。

## 2. 监控接入

### 2.1 Prometheus 抓取

端点：`GET /metrics`（文本格式，无需鉴权，仅聚合计数不含业务数据）。
抓取配置示例（prometheus.yml）：

```yaml
scrape_configs:
  - job_name: pdca-workbench
    scrape_interval: 60s
    metrics_path: /metrics
    static_configs:
      - targets: ["10.100.0.176:8768"]
        labels: { instance: "pdca-workbench-internal" }
      - targets: ["10.100.0.176:8769"]
        labels: { instance: "pdca-walkin-portal" }
```

> 若 Prometheus 不在内网，需在 Caddy 加一层带 basic-auth 的 /metrics 反代。

### 2.2 关键告警规则（Alertmanager 示例）

```yaml
groups:
  - name: pdca
    rules:
      - alert: PdcaBackupStale
        expr: pdca_backup_fresh == 0
        for: 1h
        labels: { severity: critical }
        annotations: { summary: "PDCA 数据库备份不新鲜（>36h）" }
      - alert: PdcaSyncFailed
        expr: pdca_sync_last_success_ok == 0
        for: 2h
        labels: { severity: warning }
        annotations: { summary: "PDCA 每日同步失败" }
      - alert: PdcaErrorRate
        expr: rate(pdca_errors_total[5m]) > 1
        for: 5m
        labels: { severity: warning }
        annotations: { summary: "PDCA 5xx 错误率上升" }
```

已有 `/health` 会返回 503（degraded），可继续作为 Caddy/Docker 健康检查与拨测目标；
另建议对外域名加外部拨测（UptimeRobot 等，弥补 2026-07-15 类"无人盯对外域名"事故）。

## 3. 备份恢复演练（每周）

备份每日由应用自动执行（`data/backups/pdca_*.sql`，保留 14 份）。
**每周执行一次恢复演练**，验证备份真正可用：

```bash
python scripts/backup_restore_drill.py           # 最新备份 → 临时库恢复 + 结构校验 + 自动清理
python scripts/backup_restore_drill.py --keep-scratch   # 排障时保留临时库
```

Linux cron 建议（内部工作台容器或运维机）：

```cron
0 8 * * 1 cd /opt/PDCA-agent/pdca-workbench && python scripts/backup_restore_drill.py >> /var/log/pdca_restore_drill.log 2>&1
```

> 前提：psql 客户端可用（容器内已有 pg_dump/postgresql-client-18）；`--psql` 可显式指定。
> 演练失败（返回非 0）请立即按告警通道人工介入——备份失败或损坏等于没有备份。

## 4. 回滚与灰度

- **无 schema 变更**：`deploy_release.sh` 自动回退上一提交镜像。
- **含 schema 变更**：不自动回滚；先 `pg_restore` 发布前备份，再切回上一镜像。
- 新前端切换回退 = 删除 `.env` 的 `PDCA_HOME_REDIRECT`（旧页面一直共存）。
- staging 建议：在测试机按同样 compose 配置起一套 dev 环境，PR 合并前人工验收
  `/app` 各页面（登录/驾驶舱/看板/物流/会议/获客/五件套/任务/培训/数据同步）。

## 5. 遗留整改清单（P5 未完成项，需运维执行）

| 项 | 现状 | 整改 |
|----|------|------|
| **磁盘容量治理（2026-08-19 实战教训）** | 20G 根盘 100% 满 → PG 崩溃循环（No space left on device）+ 部署全挂 | 每周 `docker image prune -a -f` + `docker builder prune -af`（保留在用镜像）；**建议云控台把 vda3 扩容到 ≥40G** |
| Docker API 无 TLS | `tcp://10.100.0.176:2375` | 改 `ssh://` 或双向 TLS 2376（`CI-CD.md` 已有指引） |
| 单主机 + 单库 SPOF | 无副本 | 评估 PG 流复制/托管高可用；至少每周演练恢复 + 异地备份副本 |
| Caddy 配置未版本化 | 手工改 Caddyfile | 纳入仓库 `deploy/caddy/` 并走发布流程 |
| 密钥轮换 | .env 明文 | SECRET_KEY 轮换会使在线 JWT 失效，需通知后批量重登；VERTU_APP_KEY 走 `vertu-cli agent env` 重签 |
| 集中日志 | 各容器本地文件 | 可选接入 Loki/云日志；至少保证 request_id 与结构化格式（后续版本） |
| schema 三轨管理 | alembic 仅 7 表 | 后续统一为单一迁移链（003 起新表全部进 alembic） |
| .env 编码 | .env.walkin 曾为无 BOM UTF-8，Windows PowerShell 5.1 Get-Content 按 ANSI 读挂 | 统一存为 **UTF-8 with BOM**（utf-8-sig）；新增配置用纯 ASCII 注释 |

## 6. 关键路径速查

| 场景 | 操作 |
|------|------|
| 看板数字异常 | `GET /metrics` 看 sync/backup 指标；`/api/admin/sync` 手动全量同步；查 `/health` |
| 新数据不上看板 | 确认 06:00 每日同步与 20:00 Sell-in 补充任务运行（调度器日志 `[alert]` 推送） |
| 备份失败 | 立即 `backup_database()`（`/api/admin/backup` 或容器内脚本）并检查 pg_dump 路径 |
| 前端空白 | 容器内 `ls /app/spa-dist/index.html`；未构建说明镜像过旧，重发布 |
| 回滚新前端 | 删 `.env` 的 `PDCA_HOME_REDIRECT`，重启容器 |
